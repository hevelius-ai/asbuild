## Premortem: how S4 could fail

1. **The README drifts from the agreed wording** (a paraphrase of D16 or G3, or a "proves" slipping in). Test: S4-C2 compares the lines byte for byte with the handover's text; S4-C3 scans for the forbidden words.
2. **A demo link points at the wrong verdict**, or a demo PR's verdict changes when the engine on main changes and its check is re-run. Mitigation: the receipts section links by number with the verdict each showed; the PR records each one's current check run, read with the wait script; the pin later freezes the engine.
3. **The real stories stall** (no code yet in auto-job-search; a story's own decision waits for the owner). Mitigation: story S1 is agreed and its build starts the morning it is approved; E1-S1's gate needs the owner's answer on coverage (open decision); the report at working day 12 counts PROVEN stories.
4. **The pin breaks the judged repositories** (a tag that does not exist yet, or templates and workflows naming different refs). Mitigation: the pin PRs are opened only after the tag exists; a test checks the templates name one ref; each pin PR's own verdict is read.
5. **The walkthrough finds a blocker late.** Mitigation: it runs on the release build as soon as the pin lands, before the owner's try, with time left in the budget.

The PR counts how many review findings fall in these five areas.
