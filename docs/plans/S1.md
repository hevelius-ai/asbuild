# S1 plan: the CI check, the verdict and the receipts

Story S1 of AsBuild Core (HANDOVER section 4). Estimate 8 to 14 agent hours; kill gate at 20 agent hours (D20). Written 10 Nov 2026, before any code.

## What S1 delivers

1. **The engine** in `hevelius-ai/asbuild`, ported from step 0 (`asbuild-spike-a/auditor/`), not redesigned:
   `engine/verdict.py`, `engine/lock_check.py`, `engine/junit_classify.py`, `engine/c3_overlay.py`, `engine/common.py`,
   plus `engine/receipt.py` (G4's `render_plain.py`, fitted to real verdicts) and `engine/lint_plain.py`.
2. **The two workflow templates**, `workflows/asbuild-test.yml` (untrusted, `pull_request`) and
   `workflows/asbuild-verdict.yml` (trusted, `workflow_run`, from main). Both fetch the engine from
   `hevelius-ai/asbuild` at `main` (D18), into the runner's temp folder, never from the judged repository.
3. **The wait script** `plugin/scripts/asbuild_wait.py`, step 0's, with an exit code for UNRESOLVED (D19).
4. **asbuild's own CI**, `.github/workflows/ci.yml`: pytest with 100% coverage of `engine/` and the wait script, ruff (lint and format), mypy. Actions pinned by commit SHA.
5. **The records** `docs/CONTROL.md`, `LOG.md`, `KNOWN-ISSUES.md`, `hours.csv`, with `DECISIONS.md` and `PARKING.md` moved from the kit. The project skill goes to `.claude/skills/asbuild-project/` without its "Starting material" section.
6. **On `hevelius-ai/asbuild-demo`:** the wiring PR (the two workflow files and a small sample app), then one story and the build PRs that show S1's criteria live (these become S4's demo).

## Small choices (reported here, inside "done")

- **Story and check IDs:** stories live in `dev-docs/stories/S<n>/story.md`; checks are `S<n>-C<m>`; each acceptance test name carries its check ID (`test_S1_C1_...`). The branch `build/S<n>` names the story; a suffix is allowed (`build/S1-retry`), so the demo can hold several build PRs for one story.
- **story.md** follows G4's `story-format.md`: a criteria table, then the plain checklist table (`ID | plain:`). The receipt quotes `plain:` word for word.
- **The receipt** is one PR comment, edited in place on every new verdict, so a PR carries one receipt. The check run's summary holds the technical report.
- **Check-run conclusions:** PROVEN success; WAITING FOR YOU action_required; NOT PROVEN and UNRESOLVED failure (never green). The title carries the verdict, and the wait script reads it: exit 0 PROVEN, 1 NOT PROVEN, 3 UNRESOLVED, 4 WAITING FOR YOU, 7 timeout.
- **No strike count:** the "try N of 3" line and the cap case (G4 cases 10 and 12) belong to the cut gate; template 4 drops the count.
- **"Tests cannot run"** means `pr.xml` or `acceptance.xml` is missing, unreadable or has no test cases.

## Acceptance tests (written first, seen failing, then locked)

In `tests/acceptance/S1/`, one per criterion, named after it. They drive the engine with recorded evidence (JUnit XML, PR file lists, trees and blobs as data); `verdict.py` gets a thin data-fetch layer so the same `judge()` runs on fixtures and in CI. The live run on the demo is the end-to-end evidence for each one.

| Check | Criterion (HANDOVER section 4) | Test |
| --- | --- | --- |
| S1-C1 | Locked tests fail on main, pass on the PR, nothing else broken: one check run "AsBuild: PROVEN" and one receipt | `test_S1_C1_proven_one_check_one_receipt` |
| S1-C2 | A locked test still fails: NOT PROVEN, receipt names the unmet check in one line | `test_S1_C2_not_proven_names_unmet_check` |
| S1-C3 | A locked test or protected file changed: WAITING FOR YOU, receipt names the file | `test_S1_C3_waiting_names_changed_file` |
| S1-C4 | Tests cannot run: UNRESOLVED, nothing else claimed | `test_S1_C4_unresolved_claims_nothing` |
| S1-C5 | No merged story: never PROVEN, WAITING FOR YOU, "no agreed check covers this change" | `test_S1_C5_no_story_never_proven` |
| S1-C6 | The verdict job runs from main and never executes PR code | `test_S1_C6_verdict_job_runs_from_main_only` (reads both workflow templates: `workflow_run` trigger only, checkout of the default branch, no `pull_request_target`, engine fetched from `hevelius-ai/asbuild`, no step runs a file from the PR) |
| S1-C7 | A story PR: WAITING FOR YOU, receipt lists the new checks' `plain:` sentences | `test_S1_C7_story_pr_lists_new_checks` |
| S1-C8 | The six receipts render from real verdicts and lint at 0 errors | `test_S1_C8_six_templates_lint_clean` |

The owner's merge of the asbuild PR approves these tests; after that a change to one is an owner decision recorded in a PR.

## Order of work and owner merges (D18)

1. asbuild PR `build/S1`: engine, templates, wait script, CI, records, tests. Review (D21), then **owner merge 1**.
2. Demo wiring PR: two workflow files and the sample app; no verdict (workflows not on main yet). **Owner merge 2.**
3. Demo story PR `story/S1`: one small story with two checks; the owner's words are a short request I draft for the sample app, which the owner approves by merging (S1-C7 live). **Owner merge 3.**
4. Demo build PRs, opened and left open for S4: correct build (PROVEN), a build that misses a check (NOT PROVEN), one that edits a locked test (WAITING FOR YOU), one whose test run ends before writing results (UNRESOLVED), and a branch with no story (WAITING FOR YOU, no story).
5. Fixes found in step 4 are batched into one asbuild PR at a time. **Expected 0 to 2 extra merges.** Each 🔴 block says how many merges remain.

Owner time for S1: about 3 to 5 merges, near 1 hour.

## Premortem: how S1 could fail

1. **A missing artifact posts no verdict at all** (step-0 fact 10), so UNRESOLVED never shows and the agent's wait times out. Test: S1-C4 runs the verdict with no evidence; the workflow's last step posts UNRESOLVED with `if: always()`, checked by a template test. Live: the UNRESOLVED demo PR.
2. **The receipt does not fit real verdicts** (step 0 wrote free text, G4 read hand-written codes), giving wrong or lint-failing receipts. Test: S1-C8 renders all six templates from `judge()` output, not hand-made scenarios, and runs `lint_plain` at 0 errors.
3. **A story PR reads as "protected file changed"**, because it edits `locks.json` and adds files under `tests/acceptance/`. Test: S1-C7 asserts template 2 with the `plain:` sentences and no protected-file wording.
4. **The workflow templates and the engine on main drift apart** (D18 fetches main): one bad engine merge breaks every judged repo's verdict. Test: asbuild CI runs each command line the templates use against fixtures. Limit: a bad merge shows as UNRESOLVED, never as PROVEN.
5. **Pull requests from forks get no verdict:** the trusted job finds the PR from the head commit, which only works for branches in the same repository. Stated limit in the README (S4), with a test row showing a fork PR gets no check rather than a wrong one. Not fixed in Core.

The PR will count how many review findings fall in these five areas.
