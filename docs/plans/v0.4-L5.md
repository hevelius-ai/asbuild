# L5 in detail: when do the new protected names apply?

> Copied from the design kit on 2026-11-15. The three design views, the review records and the proof outputs stay on the owner's computer; the proofs ran in the private repository `hevelius-ai/asbuild-proofs`.

## What "protected" does

When a pull request changes a protected file, AsBuild judges no line and says WAITING FOR YOU: "a file only you may change" (D41). It exists because those files can change how the checks run, so a pass could not be trusted.

## What v0.4.0 adds

Thirteen new names, all JavaScript settings: `package.json`, `.npmrc`, `tsconfig*.json`, `vite.config.*`, `vitest.config.*` and the like. Lock files (`package-lock.json`, `pnpm-lock.yaml`, `*.lock`) are already protected today, in every repository.

## Who is affected

Only a Python project that also holds JavaScript files: for example a Python back end with a React front end in a `frontend/` folder, whose agreed checks are all Python. A pure JavaScript project is protected either way; a pure Python project has none of these files.

## The two options

**A. One list for every repository.**
- In that Python-plus-front-end project, a build that edits `frontend/package.json` (say, a script), `tsconfig.json` or `vite.config.ts` now waits for you with no line judged, where today it can be PROVEN.
- Good: one simple rule, nothing conditional in the safety code.
- Cost: waits that protect nothing. In that project no JavaScript check exists, and the JavaScript test steps do not even run (they start only when the repository has JavaScript checks), so those files cannot change any judged result. How often such builds happen is not measured.

**B. Only once the project has JavaScript checks.**
- The names apply when main's `locks.json`, or the pull request's own, lists a JavaScript check file. (The pull request's counts too, so the first JavaScript story's receipt still says the software list changed.) Main's `locks.json` cannot be changed by a pull request, and a pull request can add lock entries only as a story, which always waits for you.
- Good: Python projects see no change at all; protection appears exactly when there is something for it to protect.
- Cost: one condition in safety-relevant code, two more conformance rows, about 1 build hour. Stated limit: a Python check that itself runs a JavaScript build (rare) would not see those files protected.

## My lean

**B, 75%** (up from 65%: writing it out showed A's extra waits guard nothing, since the JavaScript steps do not run without JavaScript checks). Fable's view leaned A (80%) for simplicity: "a pull request cannot switch it off". Under B a pull request cannot switch it off either, because the switch is main's `locks.json`.

Reply `L5A` or `L5B`.
