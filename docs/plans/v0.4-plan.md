# AsBuild v0.4.0 delivery plan: TypeScript and JavaScript (agreed by the owner on 15 Nov 2026, D48)

> Copied from the design kit on 2026-11-15. The three design views, the review records and the proof outputs stay on the owner's computer; the proofs ran in the private repository `hevelius-ai/asbuild-proofs`.

Builds the agreed design (`docs/plans/v0.4-design.md`, draft 4.1; the owner's answers of 15 Nov: 1A, L1 A, L2 A, L3 A, L4 A, L5 B, L6 A, L7 B, L8 A, L9 C). Same rules as the release just finished: locked tests first and seen failing, 100% coverage of new lines, CI decides, an independent review on every pull request (at most three rounds), the owner merges and publishes, the user walkthrough before the release is called done.

## Done (three lines, from the design)

1. In a throwaway private repository holding a small React + Vite + TypeScript app, every row of the JavaScript conformance column gets its expected verdict from the real workflows; no cheat row is ever PROVEN.
2. Python-only repositories get exactly v0.3.4's results (locked S1 to S5 tests, unit suite, golden files, the demo's four verdicts); Python repositories with JavaScript files get only the stated differences.
3. A fresh agent following only the README, in a new repository with a create-vite React + TypeScript app and a shadcn `Button`, reaches PROVEN with the same commands and merges as the Python path, plus installing Node.js 24.

## Budget (agreed, D48; playbook 1.2)

- **Agent: 30 hours, hard stop 37.** Report at 24 (80%).
- **Owner: 5 hours, hard stop 7.** Report at 4.
- **Calendar: 10 working days** (a day counts only if the agent did v0.4 work), outer limit 4 calendar weeks from the first build commit.
- **Each milestone stops at the top of its estimate** for the owner's choice (go on, cut scope, or stop).
- **Kill gate:** if M1 and M2 together pass 18 agent hours, the owner decides whether to continue.
- **Model spend:** reviews by three models at extra effort (P1 B, the owner's choice), each with its own lens, under the nine guards in `docs/plans/v0.4-scope-guard.md`: review budget $250, hard stop $300, report at $200; the walkthrough about $2. The design phase (about $77) is counted apart.

## P1: how each pull request is reviewed

The owner chose B (three models at extra effort on every pull request), with the scope guard in `docs/plans/v0.4-scope-guard.md` (G1 to G9): one lens per model; every blocking finding cites what agreed thing it breaks, else PARKED; rounds 2 and 3 only the model with an open finding, new findings only if HIGH; a volume stop (more than 8 blocking in round 1) and a divergence stop (a round finding more than the last); fix the instance, not the class; old code stays "Found, not fixed"; a review budget.
