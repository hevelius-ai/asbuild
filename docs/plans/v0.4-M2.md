# v0.4.0 M2 Test job: task plan (draft, prepared during the pause before the weekly usage reset)

Milestone M2 of `docs/plans/v0.4-plan.md` (D48). Estimate 6 to 9 agent hours; stops at 9 for the owner's choice. Kill gate:
M1 (1.4 h) and M2 together above 18 hours. One pull request, `m2/test-job`, branched from main at e6eda0d (#40 merged). Three-lens
review under the scope guard (D48), Fable's lens on Fable again after the reset. Design: `docs/plans/v0.4-design.md` §4.2,
§4.3, §4.6; proofs JS-1 to JS-22, P-CI-1, P-WIN-1, P-VITE8 (`docs/plans/v0.4-proofs.md`).

## Criteria

- **M2-C1 The JavaScript steps.** In `asbuild-test.yml` (both copies), after the Python steps and before the shared
  fails-before step, each gated by `if: hashFiles('tests/acceptance/**/*.test.*') != ''` (P-CI-1), each with
  `continue-on-error: true` and its own `timeout-minutes`: `actions/setup-node` pinned by commit, Node 24, no cache;
  `npm ci --no-audit --no-fund --legacy-peer-deps`, writing only npm's error code (`EBADPLATFORM`, `ERESOLVE`, `EUSAGE` or
  `OTHER`, by a fixed pattern) to `out/js-install.txt` on failure; the full suite
  (`node_modules/.bin/vitest run --reporter=junit --outputFile=out/pr-js.xml`); the hardened run
  (`--config "$ASBUILD/engine/js/vitest.acceptance.mjs" --root . ... --outputFile=out/acceptance-js.xml`). Tools start
  from `node_modules/.bin`, never `npm run` or `npx`. A Python repository with no JavaScript checks runs exactly v0.3.4's
  steps (done line 2).
- **M2-C2 AsBuild's Vitest settings.** `engine/js/vitest.acceptance.mjs`: Node built-ins only; reads tsconfig `paths`
  itself (`tsconfig.json`, then `tsconfig.app.json`, following relative `extends`) with a string-aware JSONC reader (a
  `**/` glob or `"@/*"` is never taken for a comment: the proof reader's bug); drops aliases for `vitest`, `@vitest`,
  `vite`, `@testing-library` and any pointing outside the project; never reads the project's Vite or Vitest config; sets
  the automatic JSX runtime (`esbuild.jsx` up to Vite 7, `oxc.jsx.runtime` on Vite 8), `setupFiles: []`,
  `globalSetup: []`, `retry: 0`, `passWithNoTests: false`, include `tests/acceptance/**/*.test.?(c|m)[jt]s?(x)`.
  Starting point: the proven `proofs/vite8-app/asbuild-c3.mjs` in `hevelius-ai/asbuild-proofs` (JS-17, JS-18, JS-20,
  P-VITE8), rebuilt with tests.
- **M2-C3 Fails before for JavaScript.** `c3_overlay.py` picks the runner by the file's extension; each JavaScript check
  file is laid over main in a worktree at `.asbuild-c3/<slug>/` inside the checkout and run with AsBuild's settings and
  the pull request's `node_modules` (JS-7); its result file keeps the `_<ext>.xml` ending (M1's `for_c3` needs it).
- **M2-C4 The live run (done line 1).** `tests/conformance/live.py` pushes the JavaScript rows' trees to a throwaway
  private repository with the real workflows, reads the posted verdicts and compares them with `cases.json`'s live rows
  (`live-vite5..8-proven` and `-existence-only`, `live-js-story-repairs-lockfile`, `live-js-column`). It also checks the
  saved verdict file (D50) with `asbuild_wait.py` on a real run (M1b's premortem 1).
- **M2-C5 The engine pin.** The four templates pin the new engine tree id; the live repository's workflows clone the M2
  branch in place of the release tag (test-only; the templates keep `v0.3.4` until M4, D49).

## Tests first

- Workflow tests (`tests/unit/test_workflows.py` style): the gates, the order (JavaScript after Python, before fails
  before), `continue-on-error`, timeouts, the pinned `setup-node`, the install-code pattern, no `npm run`/`npx`.
- The settings file: tests run with `node --test` (needs Node 24 in AsBuild's own CI: one added CI step, to state in the
  pull request), covering the JSONC reader (comments, strings with `/*` and `**/`, trailing commas), `extends` chains,
  the alias drops, the JSX keys per Vite major, the fixed settings. Coverage of the `.mjs` file with Node's own coverage
  (to settle at plan review: the playbook asks 100% of new lines).
- `c3_overlay.py`: the runner choice by extension and the result file names (Python unit tests, no Node needed).

   run (the cost: no coverage number for it).

   change.
