## Criteria

- **M4a-C1 (K4) The note is current when the check finishes.** In the verdict workflow (both copies) the receipt is
  posted before the check run, and the verdict file is saved right after the check run, as today: so by the time the
  check named "AsBuild" completes, and by the time `/asbuild:verdict` reads the saved verdict, the note already shows
  this commit's verdict. The receipt step makes `out/` itself (today it relies on the check-run step, which ran first).
- **M4a-C2 (K7) A story pull request that carries app code says so.** When a story pull request changes any file other
  than the new story's own (its tests, its story and request files, `locks.json`, `.claude/settings.json`) and other
  than a protected file (which already has its own line), the verdict stays WAITING FOR YOU and the note adds one line
  in plain words, with the number of such files, never their names (a file name is the pull request's text, and the
  plain-words lint bans names): "It also changes N other files of your app, which AsBuild hasn't checked; approving
  the checks adds those changes too." and the action 'If you didn't ask for that, tell the AI: "Keep only the new
  checks in this change, and put the other changes in a separate one."' The technical report lists the paths.
- **M4a-C3 (K9, option B) Results a pull request commits are not read as real ones.** A change to any file under the
  repository's root `out/` folder, where the test job writes its result files, or to the path `out` itself (a link
  pointing elsewhere; round 1, B1), is a protected change: WAITING FOR YOU,
  named in the note as "the folder where your checks' results are written". The test job's Python steps stay
  v0.3.4's (done line 2). Stated limits, unchanged: files already on main under `out/` are still read; a pull
  request's own code can still write results while it runs (D16 line 3).
- **M4a-C4 (K8, the owner's option A) Story text cannot add links, images, mentions or formatting under AsBuild's
  note.** The story's title and each plain line are shown as written, never as Markdown. An ordinary line (only
  letters, digits, spaces and `, . ; ? ! ' " % ( ) -`, a colon only before a space; no word mixing letters and
  digits, no run of seven hex characters, no `www.`) is left exactly as it is, so receipts stay byte for byte
  v0.3.4's (done line 2: the golden files and the locked S1 checks). Any other line is escaped whole: a backslash
  before every ASCII punctuation mark, an invisible word joiner between every two visible ASCII characters, and one
  on both sides of every dollar sign, at the line's ends too (round 1, B2 and B3: characters outside ASCII get none
  beside them, so accents, emoji and other scripts stay whole). Proved on GitHub's own renderer (`POST /markdown`, before any code): a backslash alone stops
  HTML, emphasis and link syntax but not mentions, `#43`, `GH-1`, commit ids, e-mail addresses, emoji or formulas; the
  word joiners stop all of them, and the text shown is the person's, character for character. The plain-words lint
  reads the text as shown. A small addition inside A, reported here: escaping every line, the first build, broke four
  locked S1 checks and nine golden receipts (the same visible text, other bytes), so ordinary lines are left alone.
  The Level 2 live run (`tests/conformance/live.py`) gets two rows: `live-story-text` (a story whose title and plain
  line hold a mention, a link, an image, a web address, references, an emoji code and HTML, with one app file beside
  it: K7 and K8; GitHub's rendered note must hold no link, image, mention, reference, emoji or formula and must show
  the words character for character) and `live-out-folder` (a build committing `out/c3/forged.xml`: K9). Every live
  row also checks K4: the note was last written no later than the check run completed. Run on this branch before
  review (those two rows and `js-proven`), and in full on the release pull request after its refresh.
