## Criteria

- **M3-C1 Story-time checks for JavaScript** (`plugin/scripts/asbuild_story_check.py`). The language is chosen by the
  extension of the story's files: `tests/acceptance/S<n>/` holding `*.test.[cm]?[jt]sx?` files takes the JavaScript
  path; a story mixing Python and JavaScript files, or holding any other file beside its JavaScript check files, is
  refused in plain words. The Python path is v0.3.4's, unchanged (its tests, S2's locked checks).
  - **The scanner** (standard library): reads each check file with comments, strings, template literals and regular
    expressions skipped; finds exactly one top-level `test(` or `it(` call, written at the start of a line, whose first
    argument is a literal title with no escape and no `${` that starts with one of this story's check IDs; refuses
    `describe`, `suite`, `xit`, `xtest`, `fit`, `fdescribe`, `xdescribe` and any member of `test`, `it` or `describe`
    (`.only`, `.skip`, `.todo`, `.each`, `.fails`, `.skipIf` and the rest), and a nested `test(`. The titles it finds
    must equal the titles the lock records for the file (the same rule as `engine/langs.py`'s `JS_TITLE`), so a
    `test(` line inside a comment or string is refused, never locked. One file per check, one check per file.
  - **The Vitest table** (design §4.4): Vite 5 and 6 with Vitest 3.2.x, Vite 7 with 4.1.x, Vite 8 with 5.1.x, read
    from the installed `node_modules/vite/package.json` and `node_modules/vitest/package.json`; any other Vite or Vitest
    is refused in plain words, naming the first story's command. No Vitest installed: the checks cannot run (exit 2),
    naming the same command.
  - **Fails on main, by an assertion:** the story's files are laid over the base in a git worktree inside the checkout
    (`.asbuild-story/`, cleared first and removed after, so the project's `node_modules` is found: JS-7) and each runs as
    `node <repo>/node_modules/vitest/vitest.mjs run <file> --config <AsBuild's settings> --root . --reporter=junit`
    (P-WIN-1: the form that starts on Windows), with a limit of 120 seconds per file. A result with
    `type="AssertionError"` passes; a pass, a skip, a file that could not load, a failure the engine counts as
    existence-only ("a part does not exist yet"), an empty `type` or any other failure is refused, each with its own
    plain line (the Python path's wording where one exists). No `node` on the computer: the checks cannot run.
  - **AsBuild's settings at story time:** the plugin carries a byte-equal copy of `engine/js/vitest.acceptance.mjs`
    (`plugin/js/vitest.acceptance.mjs`; a test keeps the two equal), so story time and the test job run the checks
    the same way.
  - **Examples as literals:** each approved example must appear as a string literal (or a number written the same way)
    inside an `expect(...)` chain of its check's test: from `expect(` through every chained `.matcher(...)`. A
    variable, a regular expression or a template with `${` does not count. The match rule is the Python path's
    `example_matches` (whole values; 4 characters or more for a part).
  - **The lock:** `--lock` locks the story's JavaScript files with the engine's entry (normalised hash, the literal
    titles), and adds the deny rule as for Python. A test compares the story check's entries with
    `engine/lock_check.entry` on every JavaScript fixture.
- **M3-C2 The first story's repair and install command** (`plugin/scripts/asbuild_js.py`, standard library, also the
  shared JavaScript facts for setup and the story check: the Vitest table, the stop list, the version readers).
  `python asbuild_js.py tools`, run once by the story skill in a JavaScript project's first story: checks Node 24 or
  newer and npm 11.19 or newer; refuses when `origin/main`'s `locks.json` already lists a JavaScript check (the tools
  came with the first story); removes `node_modules`; drops from `dependencies` and `devDependencies` only (never
  `optionalDependencies`) every name matching the proven rule `-(darwin|win32|linux|freebsd|android)-(arm64|x64|ia32|
  arm)(-|$)`, and says which; rewrites the lockfile with `npm install --package-lock-only --no-audit --no-fund
  --legacy-peer-deps`; reads the Vite major from the lockfile (`packages["node_modules/vite"].version`) and refuses
  one outside 5 to 8; then runs the one named command, `npm install --save-dev --save-exact --no-audit --no-fund
  --legacy-peer-deps vitest@<3.2.4 | 4.1.12 | 5.1.0> jsdom @testing-library/react @testing-library/dom` (the exact
  pins proven in JS-17 and P-VITE8). Each npm failure stops with npm's own last lines and changes nothing more.
- **M3-C3 Setup's JavaScript path and the one stop list** (`plugin/scripts/asbuild_setup.py`, reading main's tree as
  it reads files today). In this order: a `.py` file anywhere, or `requirements.txt` or `pyproject.toml` at the root:
  Python, exactly as today; else a root `package.json`: JavaScript; else a `package.json` below the root: stop, "not
  yet" (an app only in a subfolder); else Python as today. A JavaScript repository is checked against the one stop
  list in `asbuild_js.py` (design §3.1's last row): `package.json` unreadable; workspaces (`workspaces` in
  `package.json`, or `pnpm-workspace.yaml`); Next.js (`next`); no `react`, or `react-native`; no `vite`, or a Vite
  outside 5 to 8; a Vitest already listed that is not the table's for the app's Vite; Jest without Vitest; Playwright
  (`@playwright/test` or `playwright`); then this computer's Node older than 24 or npm older than 11.19, or missing,
  with the install line. Versions are read from `package-lock.json` when it lists the package, else from
  `package.json`'s range. A JavaScript repository that passes gets the two workflow files and nothing else (no
  `requirements.txt`), and one plain line: AsBuild adds its test tools in the first story. Small addition (design
  intent, done line 3): on an empty GitHub repository whose folder holds a root `package.json` and no Python marker,
  setup stops and asks the person to upload the app as `main` first, instead of making a `requirements.txt` commit
  that would turn the app's repository into a Python one for good (design §3.2: both files at the root stay Python).
  Each of the twelve setup rows of `cases.json` runs through the real classification (`tests/conformance/
  test_setup_rows.py`, trees stored as fixtures).
- **M3-C4 `javascript.md`** (`plugin/skills/story/javascript.md`), linked from the story skill (which stays under 100
  lines: S2-C3): when to use it (a root `package.json` and no Python marker, as setup decides); the first story's
  command (M3-C2) and that its `package.json` and `package-lock.json` changes go in the story pull request (the
  receipt's `STORY_ADDS_TOOLS` line); one file per check, `tests/acceptance/S<n>/S<n>-C<m>.test.tsx`, one top-level
  `test("S<n>-C<m> ...")`; `// @vitest-environment jsdom` on the first line; render what the person sees (a page inside
  `MemoryRouter`, or, where `App` holds its own router, `App` after `window.history.pushState` to the page's address);
  assert each approved example literally inside `expect(...)` (`expect(document.body.textContent).toContain("Saved")`),
  never with a variable, a regular expression or `getBy...` for the approved words; never a setup file, a mock of the
  app's own code or a change to Vite, Vitest or tsconfig settings; no network.
- **M3-C5 The verdict skill lines** (`plugin/skills/verdict/SKILL.md`): UNRESOLVED names `package.json` and
  `package-lock.json` beside `requirements.txt` as files to fix in their own pull request, and the install sentence
  as the cause to report; WAITING FOR YOU says that in a JavaScript app a build that adds or changes a package waits
  for the person (`package.json` is protected whole, L4 A).
- **M3-C6 The README and the plugin's description** (design §4.5): under "Before you start", the install line for
  Node.js 24 or newer with npm 11.19 or newer (for JavaScript projects); one needs line for a TypeScript or
  JavaScript app (React with Vite 5 to 8; AsBuild adds Vitest in the first story); the line for an empty repository
  holding a JavaScript app (upload it as `main` first); the Claude Code paste message's first step checks Node and npm
  for such a project; an unnumbered line under "What AsBuild does not prove": in a JavaScript project only Vitest tests
  count as the app's other checks. S4-C2's four numbered items stay. The plugin's `plugin.json` description and
  `plugin/README.md` name React with Vite beside Python (the version number stays 0.3.4 until M4).

## Premortem

1. **The scanner and the lock disagree** (a title the lock records but the scanner skips, or the reverse), so a
   check is locked that the verdict never finds. Test: the scanner's titles must equal `JS_TITLE`'s for every
   fixture, and a file where they differ is refused.
2. **A check written as the skill says still fails on main for the wrong reason** (a router inside a router, a missing
   jsdom environment, `getByText` throwing instead of asserting), so the person is stuck at story time. Evidence 1 on
   the create-vite and Lovable apps; each refusal names the fix; `javascript.md` covers the two router shapes.
3. **The repair on the person's computer breaks the install on GitHub.** Proven 4 of 4 (JS-19 Mac, JS-22 Windows with
   npm 11.19.1); evidence 1 repeats it with the product's code; the npm floor stops older npm in setup and in
   `tools`. Stated limit (design premortem 2): a platform-only package added by a later build is caught only on
   GitHub (UNRESOLVED).
4. **Setup sends a Python repository the JavaScript way, or the reverse** (done line 2). The twelve setup rows; the
   Python path's existing tests and S5's locked checks unchanged; the empty-repository case.
5. **Scope creep** (design premortem 5): only the files named here change; setup stops for exactly the stop list;
   anything else is one parking line. `engine/` does not change, so the engine pin stays d9e1d74.
