# K1: no "works" line under a changed protected file (release `v0.3.1`)

Decision S5-2A (D41). Known issue K1 (found 10 Nov, S1 re-check after D25): a pull request that changes a file only the person may change, outside `tests/acceptance/` (a settings file such as `pytest.ini` or `pyproject.toml`, the requirements, the workflows), gets WAITING FOR YOU, but its checklist lines are still judged, so they can read "✓ works" under the "Stop" headline. Such a file can change how the checks run (for example `addopts = -p <module>` in `pytest.ini` loads a module from the repository even with plugin autoload off), so those lines cannot be trusted.

## The change

- `engine/verdict.py`: as D25 does for a changed acceptance file, any `PROTECTED_CHANGED`, `LOCK_CHANGED` or `LOCK_DELETED` leaves every line of the checklist unjudged, with the new status `file_changed`. A changed acceptance file keeps its own status, `check_changed`.
- `engine/receipt.py`: `file_changed` reads "? not judged: the AI changed a file only you may change"; when every line is unjudged, the footer claims nothing (as K2).
- `docs/KNOWN-ISSUES.md`: K1 fixed.

The verdict itself does not change: such a pull request was WAITING FOR YOU before and still is. The cost the owner accepted: a build that also adds a package to `requirements.txt` shows no line results; the person adds the package in its own pull request first, as the verdict skill already says.

## Tests first, seen failing

`tests/unit/test_verdict.py::test_K1_changed_protected_file_leaves_every_line_unjudged`, for `pytest.ini`, `pyproject.toml`, `requirements.txt` and a workflow file: every line `file_changed`, no ✓ or ✗, the new words twice, no footer claim, the receipt passes the plain-words lint. Seen failing before the fix: `assert {'works'} == {'file_changed'}`, all four cases. The locked S1 checks (C3: WAITING FOR YOU names the changed file; C8: template 2 lints clean and shows both lines) still pass.

## Premortem

1. A locked check expects judged lines under a protected change. Test: the full suite; S1-C3 and S1-C8 read the template and the file's name, not the status.
2. The new words break the plain-words lint. Test: the K1 test lints the receipt.
3. Setup's own update pull requests lose information. Stated limit: they have no story, so no lines.
